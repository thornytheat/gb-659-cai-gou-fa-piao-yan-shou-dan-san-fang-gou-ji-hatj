# 数据字典

- run_id：规则版本与输入 SHA-256 前 12 位组成的稳定批次标识。
- line_no：从 1 开始的物理来源行号，不因隔离或排序改变。
- business_key：本项目声明的业务唯一键，始终按字符串存储。
- reason_code：隔离原因的稳定英文编码。
- accepted：进入业务计算的记录数。
- quarantined：保留证据但不参与业务计算的记录数。
- 数值：金额、税额、用量和权重使用 Decimal；对外序列化为字符串。
- 时间：存储为带偏移的 ISO 8601，分桶使用半开区间。
- 空值：缺失键、空串和业务哨兵分别记录。
- 幂等：完整输入字节与规则版本相同则复用 run_id，不新增结果。

## 数量双账（M3）

数量事件按下表拆分到两套余额，互不覆盖：

| 事件 kind | 含义 | 履约账（待收货） | 实存账（在手） |
|---|---|---|---|
| `ORDER` | 订单 | +数量 | — |
| `RECEIPT` | 验收 | -数量 | +数量 |
| `RETURN` | 真实退货 | +数量（重开待收货） | -数量 |
| `SHRINKAGE` | 盘亏 | 不变 | -数量 |
| `RECOVERY` | 找回 | 不变 | +数量（冲回原盘亏） |

- 待收货量 = 订单 - 验收 + 退货。盘亏与找回不改变待收货量，避免把仓储损失算成供应商少交货。
- 实存数量 = 验收 - 退货 - 盘亏 + 找回。冻结盘亏不进入实存，避免虚增可用库存。
- 未找回数量 = 盘亏 - 找回，找回不得超过该值。
- 双账勾稽桥：实存数量 = 净验收数量 - 未找回数量。
- `event_id` 在业务键内唯一；同一事件重放不重复记账，数量或类型不同则判冲突。
- `expected_version`：找回事件必填；与当前版本不一致时拒绝，防止并发下按过期状态冲回。
- 一次事件的事件行与余额行在同一 SQLite 事务内提交；中断即整体回滚，原余额保留。
- 数量事件不产生金额、税额，也不处理付款或撤销。
